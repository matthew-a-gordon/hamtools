# Reference data is offline-first and fetched only through one rate-limited client

Park and summit reference data is cached on disk and spots are kept in memory only. Every external request goes through a single `ReferenceClient` that has no unthrottled method: spots at most once a minute, a one-second gap between any two requests, exponential backoff from a minute to an hour, a descriptive User-Agent. Config may slow these limits but never speed them. Nothing is fetched at startup; fetching happens on an explicit refresh, on saving a plan, or on the first lookup, and network work never blocks the radio, the Log or CW. We chose this over per-Activity fetching because the limits must be reviewable in one place, and because the SOTA API's terms bar AI-generated software without the owner's approval, so no SOTA API call is made until that approval exists. The daily download of the published summit list file (`summitslist.csv`) is not an API call and is allowed under this rule.
